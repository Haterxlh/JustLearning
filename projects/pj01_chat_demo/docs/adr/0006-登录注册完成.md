# 登录注册完成（第 2 步）

2026-10-20 按 `ws02_web-generation-platform/backend-uv-fastapi` 的分层写了用户模块，六条 curl 全部通过。

## 决定

- 目录按 `api` / `core` / `models` / `schemas` / `services` 分层，与既有项目一致；`app/agent/` 保留给后续 agent 逻辑。
- 业务规则写在 `AuthService`（`app/services/auth_service.py`），路由层只收请求、转调 service；注册查重返回 409，登录失败返回 401。
- 密码哈希直接用 `bcrypt`：12 轮，`password_hash` 里存 `$2b$12$...`，密码长度在 schema 里限制 8 到 72 字符。
- JWT 用 HS256，载荷 `sub` 存用户 UUID、`exp` 取 `.env` 的 `JWT_EXPIRES_MINUTES`，依赖 `get_current_user` 统一返回 401。
- 登录响应带 `user` 字段（`LoginResponse`），前端登录后无需再请求 `/me`。
- 建表放在 `lifespan` 的 `create_all`，不用 alembic。

## 考虑过的选项

- 平铺八个文件、路由里直接写 SQL 与业务判断：模块一多就乱，且与既有项目的读代码习惯不一致。
- 用 alembic 做迁移：本期表结构在开发期频繁变，`create_all` 幂等，重启即生效；上线需要保留历史数据时才引入迁移。
- 用 passlib 封装 bcrypt：passlib 1.7 与 bcrypt 4 的参数探测有告警，直接用 `bcrypt` 少一层。

## 后果

- 验收通过：注册 201、重复注册 409、密码 3 位 422、错误密码 401、登录 200 带 token、无令牌访问 `/api/auth/me` 401。
- PowerShell 5.1 传参会吃掉 JSON 里的双引号，验收请求体改放 `backend/tmp/*.json`，用 `curl.exe --data-binary "@文件"` 发送。
- 下一步做第 3 步的建表：`conversations` 与 `messages`。
