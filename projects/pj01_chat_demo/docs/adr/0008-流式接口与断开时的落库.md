# 流式接口与断开时的落库（第 3 步小步 C）

2026-10-20 加上 `POST /api/chat/stream`，端到端跑通，并修掉一个只在客户端断开时才暴露的缺陷。

## 决定

- 职责分工：`api/chat.py` 的 `chat_stream` 校验会话归属、写入用户消息、取出上下文，然后返回 `StreamingResponse`；`services/stream_service.py` 的 `stream_assistant_reply` 是异步生成器，负责转发增量并在结束时写库。
- 用户消息走请求带来的 `db` 会话，助手消息走生成器自己开的 `SessionLocal()`。原因是响应开始发送后请求会话就关闭，生成器活得比请求久。
- 上游调用用 `httpx.AsyncClient(timeout=None)`，读超时关掉，避免长回答被 5 秒默认值掐断。
- 结束帧用 OpenAI 兼容接口的 `data: [DONE]`；上游报错时发一帧 `data: {"error": ...}`，因为响应头已经发出，改不了状态码。
- 响应头加 `Cache-Control: no-cache` 与 `X-Accel-Buffering: no`。

## 关键缺陷与修法

现象：流式中途切断客户端，已生成的部分没有写进库。服务端日志出现

```
asyncio.exceptions.CancelledError: Cancelled via cancel scope ... by <Task ... run_asgi()>
Exception terminating connection <AdaptedConnection ...>
```

原因：客户端断开时 uvicorn 取消这个 ASGI 任务，生成器在 `finally` 里执行，取消状态下的第一个 `await` 立刻抛 `CancelledError`，`async with SessionLocal()` 的提交没走到。

修法：把写库整段放进 `with anyio.CancelScope(shield=True):`，屏蔽外层取消，等提交完成再结束。写库代码抽成 `save_reply(conversation_id, reply)`。

## 验证（2026-10-20 实测）

脚本 `backend/tmp/verify_stream.py` 打真实接口与真实 DeepSeek 服务：

- 首帧 3.465 秒，末帧 3.876 秒，帧间隔跨度 0.411 秒，136 帧，说明边生成边推送。
- 响应头 `content-type: text/event-stream; charset=utf-8`、`cache-control: no-cache`。
- 落库两条消息，assistant 内容与所有 `delta` 拼接结果完全一致。
- 断开用例：收到 3 帧后关闭连接，库里有 user 与部分 assistant（收到 4 字，落库 6 字，多出的一帧在途）。
- 修前同一用例失败，修复后通过；`pytest` 23 个用例全过。

## 后果

- `requirements.txt` 增加 `anyio>=4.4`，`httpx` 从测试段移到运行时。
- 断开场景无法用 `ASGITransport` 覆盖（它不模拟连接断开），只能靠 `tmp/verify_stream.py` 这类端到端脚本验证。
- 前端接入前，后端侧三个接口与流式链路已完整可用。
