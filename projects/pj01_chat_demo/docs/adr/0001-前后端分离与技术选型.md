# 前后端分离与技术选型

2026-10-20 开工。本人要求这个 demo 同时练前端与后端：界面做 DeepSeek 网页版的双栏布局（左侧会话列表、右侧消息流），后端保存会话与消息历史并用 SSE 推流，数据库用 pgvector。据此定下目录、选型与环境方式。

## 决定

- 目录分 `backend/` 与 `frontend/`，同级放置；README 只写目标、接口契约、分步计划与协作约定。
- 前端用 Vite + React + TypeScript，linter 选 ESLint。理由：插件生态最广，`typescript-eslint` 与 React Hooks 规则齐全，社区资料按 ESLint 写；Oxlint 用 Rust 实现、速度快，规则覆盖少，这个项目体量小，速度差异感觉不到。
- 后端用 FastAPI + SQLAlchemy 2.0 异步 + asyncpg + Pydantic v2；JWT 用 PyJWT，密码哈希用 bcrypt。
- 虚拟环境用 uv 创建，依赖固定为 `backend/requirements.txt`；虚拟环境内不装 pip，装包统一用 `uv pip`。
- 数据库用 `pgvector/pgvector:pg18` 容器，容器名 `justlearning-pj01-pgvector`，宿主 5433 映射容器 5432，卷 `pj01_pgvector_data`，库名 `chatdemo`，用户与密码都是 `chat`。
- 流式输出：后端用 `StreamingResponse` 输出 `text/event-stream`，每段一帧 `data: {"delta": ...}`，结束帧 `data: [DONE]`；前端用 `fetch` 加 `ReadableStream` 读取，`EventSource` 带不了 `Authorization` 头。
- 模型走 OpenAI 兼容接口，地址、模型名、密钥从 `.env` 读取，代码里不写死。

## 考虑过的选项

- 单进程由 FastAPI 直接返回页面：练不到前端组件与跨端口调试，改一次界面要重启后端。
- 中间加一层 Node 转发模型请求：多一层，演示价值低。
- 先用 SQLite 起步：pgvector 的容器、扩展与向量列做法练不到，后面接检索要重做。

## 后果

- 前端 5173 与后端 8000 分端口，后端放行 5173 的 CORS；Vite 顺延端口时 CORS 配置跟着改。
- 浏览器不接触模型密钥，请求都经后端。
- 进度与决定都写进 `docs/adr/`，README 不记进度。
