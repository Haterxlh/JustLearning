# 提问记录｜2026-10-20

## `python -m venv .venv` 命令的作用是什么

创建项目专用的 Python 虚拟环境。`python` 使用当前 PATH 里的解释器；`-m venv` 把标准库里的 `venv` 模块当程序运行；`.venv` 是环境目录名，相对当前目录。执行后生成一套独立的 `python.exe`、`pip.exe` 与 `site-packages`，装包不影响 Anaconda 全局环境，删掉目录即清除。激活只是把 `.venv\Scripts` 插到 PATH 前面，不激活时直接调用 `.\.venv\Scripts\python.exe` 效果相同。

## `python -m venv` 与 `uv` 在创建虚拟环境上的区别是什么

`venv` 只创建环境目录。`uv` 把创建环境、安装依赖、锁版本、管理 Python 版本连成一套：创建是亚秒级，装依赖比 `pip` 快数倍；依赖写在 `pyproject.toml`，`uv.lock` 记录精确版本与哈希；`uv python install` 能自行下载解释器。两者生成的环境目录结构与激活方式一样，`uv` 建的环境不带 `pip`，装包用 `uv pip install`。

## `npm create vite@latest frontend -- --template react-ts` 命令各参数的含义是什么

用 Vite 官方脚手架生成 React + TypeScript 项目。`npm create` 等价于 `npm init`，执行名为 `create-xxx` 的包；`vite@latest` 被 npm 自动补成 `create-vite` 并取最新版本；`frontend` 是生成目录名，文件落在 `./frontend`；`--` 是分界符，后面的参数原样传给脚手架；`--template react-ts` 选 React 加 TypeScript 模板。它只生成源码文件，不下载依赖，`node_modules` 由 `npm install` 安装。

## ESLint 与 Oxlint 的区别是什么，本地项目应当选哪一个

ESLint 用 JavaScript 实现，插件生态最广，`typescript-eslint`、`eslint-plugin-react-hooks` 等规则齐全，配置文件是 `eslint.config.js`，速度较慢。Oxlint 用 Rust 实现，启动与检查快一个量级，零配置可用，配置文件是 `.oxlintrc.json`，插件与规则覆盖少于 ESLint，部分类型相关检查缺失。这个 demo 选 ESLint：体量小，速度差异无感，教程与报错信息都能与社区资料对上。该选择只影响 `npm run lint` 的输出。

## `docker run` 启动 pgvector 容器的各个参数分别起什么作用

`docker run` 由镜像创建新容器并启动。`-d` 让容器在后台运行，命令立刻返回容器 ID。`--name pj01-pgvector` 给容器起名，后续 `docker exec`、`docker stop`、`docker rm` 用这个名字指定容器，省略时 Docker 随机生成名字。`-e` 传环境变量，`POSTGRES_USER=chat`、`POSTGRES_PASSWORD=chat`、`POSTGRES_DB=chatdemo` 是官方 PostgreSQL 镜像约定的三个变量，容器第一次启动、数据目录为空时据此创建超级用户与同名数据库，之后启动直接沿用已有数据，这三个变量不再生效。`-p 5433:5432` 做端口映射，冒号前是宿主端口、冒号后是容器内端口，容器内的 PostgreSQL 监听 5432，宿主改用 5433 避免与本机已有的 PostgreSQL 冲突。`-v pj01_pgvector_data:/var/lib/postgresql/data` 挂载命名卷到容器的数据目录，卷由 Docker 管理、存放于宿主磁盘，删除容器或重建容器都不丢数据，卷本身要用 `docker volume rm` 才删除。最后的 `pgvector/pgvector:pg16` 是镜像名与标签，该镜像基于 PostgreSQL 16 并预装 vector 扩展的二进制文件，因此只需执行一次 `CREATE EXTENSION` 启用，不用编译扩展源码。

## PostgreSQL 18 镜像的数据目录与卷挂载路径为什么变了

官方镜像从 PostgreSQL 18 起把 `PGDATA` 改成带主版本号的 `/var/lib/postgresql/18/docker`，并把镜像声明的 `VOLUME` 从 `/var/lib/postgresql/data` 上移到 `/var/lib/postgresql`。这样同一个卷里可以并存多个主版本的数据目录，跨大版本升级时挂载整个 `/var/lib/postgresql` 就能让 `pg_upgrade --link` 直接复用文件，不用先拷数据。沿用 pg17 的写法把卷挂在 `/var/lib/postgresql/data`，真实数据会落在镜像自动创建的匿名卷里，命名卷始终为空，容器删掉后数据等于丢失。正确的写法是 `-v pj01_pgvector_data:/var/lib/postgresql`。

## FastAPI 的 `lifespan` 是什么，`yield` 在这里起什么作用

`lifespan` 是 FastAPI 约定的应用生命周期函数：服务器启动完成、开始接收请求之前执行一遍，进程关闭时再执行一遍。`yield` 之前的代码属于启动阶段，`yield` 之后的代码属于关闭阶段，`yield` 本身把函数切成两半并在此挂起，请求处理期间两半都不执行。用法上是把异步生成器交给 `@asynccontextmanager` 装饰，生成器对象变成异步上下文管理器，FastAPI 在启动时对它做 `async with`，关闭时退出这个 `async with`。这种写法替代了旧版的 `@app.on_event("startup")` 与 `@app.on_event("shutdown")`，把资源的创建与释放写在同一个函数里，成对出现，异常路径也只走一处。

## `yield` 在生成器里到底做了什么

函数体里出现 `yield` 就变成生成器函数，调用它不执行函数体，只返回生成器对象。对生成器调用 `next()` 时开始执行到 `yield` 处暂停并把值交出去，再次调用从暂停的位置继续往下。被 `@asynccontextmanager` 包装后，这个暂停点被解释为「资源已就绪、把控制权交回调用方」，`async with` 代码块结束时继续执行 `yield` 之后的清理代码。`lifespan` 里的 `yield` 因此只是一个分段标记，不向外传值。

## PowerShell 里 `curl.exe -d '{"email":"..."}'` 为什么返回 422 JSON decode error

Windows PowerShell 5.1 在把参数交给本机程序前会重新拼接命令行字符串，单引号包住的双引号在这一步被吃掉，curl 收到的是 `{email:alice@example.com,...}`，不是合法 JSON，FastAPI 因此在解析请求体时返回 422 `json_invalid`。两种写法可以避开：在参数序列开头加 `--%`（停止解析标记，其后的内容原样交给 curl，引号保留）；或改用 `Invoke-RestMethod -Body '{"email":"..."}'`，字符串由 PowerShell 自己的参数绑定传过去，不经过命令行重拼。实测这台机器加 `--%` 仍然吃掉引号，可行的写法是把请求体放进 `backend/tmp/*.json`，用 `curl.exe --data-binary "@tmp/xxx.json"` 发送。

## `app/models/conversation.py` 顶部这些 import 各自的作用

`import uuid` 与 `from datetime import datetime` 是标准库。`uuid.uuid4` 用在 `default=uuid.uuid4`，插入时由 Python 生成主键值；`datetime` 只出现在 `Mapped[datetime]` 的类型注解里，给类型检查器和 ORM 声明列类型用。

`from pgvector.sqlalchemy import Vector` 提供向量列类型，`Vector(1024)` 映射成 PostgreSQL 的 `vector(1024)`，Python 侧读写的是 `list[float]`。

`from sqlalchemy import DateTime, ForeignKey, Index, String, Text, func` 里，`DateTime(timezone=True)` 对应带时区的 `timestamptz`；`String(200)` 是有长度上限的变长字符串，`Text` 是不限长度；`ForeignKey("users.id", ondelete="CASCADE")` 声明外键并让数据库在删除父行时级联删除子行；`Index(...)` 建复合索引；`func.now()` 放在 `server_default` 里，生成 `DEFAULT now()`，插入时由数据库填当前时间，不走 Python 时钟。

`from sqlalchemy.dialects.postgresql import UUID` 是 PostgreSQL 原生 `uuid` 类型，`as_uuid=True` 让驱动在两端自动转换，Python 侧拿到的是 `uuid.UUID` 对象而不再是字符串。

`from sqlalchemy.orm import Mapped, mapped_column` 是 SQLAlchemy 2.0 的声明式写法：`Mapped[...]` 用类型注解声明列会返回的 Python 类型，`mapped_column(...)` 接列参数（主键、默认值、外键等）。`Mapped[str]` 这种不带 `| None` 的注解默认为非空列，`Mapped[list[float] | None]` 表示可空。

`from app.core.db import Base` 是全部模型的声明基类，继承它的类会被登记到 `Base.metadata`，`lifespan` 里的 `create_all` 遍历这份元数据建表；子类不继承它，表就不会被创建。

## `model_config = ConfigDict(from_attributes=True)` 是什么意思

pydantic 的模型默认只从 `dict` 读输入，`ConversationResponse(**{"id": ...})` 这类写法才行。加上 `from_attributes=True` 后，`model_validate` 与 FastAPI 的响应序列化会改用「读对象属性」的方式取值：传入一个 ORM 的 `Conversation` 实例，pydantic 按字段名去取 `id`、`title`、`created_at`、`updated_at` 四个属性，取不到就报校验错误。没有这条配置，路由返回 ORM 对象时 FastAPI 会抛 “Input should be a valid dictionary or instance of ...”。同一个配置也让 service 层的 `LoginResponse(user=user)` 可以直接接收 `User` 对象。

## `@staticmethod` 在 `ChatService` 上起什么作用

装饰器把方法变成静态方法：调用时不自动传入 `self` 或 `cls`，第一个参数就是业务参数。`ChatService.list_conversations(db, user)` 因此能直接按类名调用，不需要先 `ChatService()` 造实例。去掉装饰器后 Python 会把 `db` 当成 `self` 传进去，参数错位，且不实例化调用会报缺少参数。用类包住而不是写成模块级函数，是为了把同一领域的规则归在一起，与 ws02 的 `UserService.register(db, req)` 写法一致。

## 为什么 `@router.get("")` 与 `@router.post("")` 写在同一个路径上不冲突

路由匹配看的是「路径加 HTTP 方法」两个维度。Starlette 遍历路由表时先按路径正则匹配，再看这条路由登记的 `methods` 集合里有没有本次请求的方法；不匹配就跳过继续找下一条。`GET /api/conversations` 只命中 `list_conversations`，`POST /api/conversations` 只命中 `create_conversation`。如果只登记了 POST 而发来 GET，找不到任何匹配的路由，Starlette 返回 405。`/api/conversations` 与 `/api/conversations/{conversation_id}/messages` 是不同路径，靠路径正则区分，不会互相遮挡。

## Starlette 是什么

Starlette 是一个用 Python 写的轻量网页框架，负责把 HTTP 请求变成 Python 函数调用、再把返回值变回 HTTP 响应。它提供路由表、中间件、请求与响应对象、生命周期事件、静态文件与测试客户端。FastAPI 的 `FastAPI` 类直接继承 Starlette 的 `Starlette` 类，`app.router`、`app.add_middleware(...)`、`app.router.lifespan_context(app)` 执行的都是 Starlette 的代码。FastAPI 在它之上加了请求参数校验、依赖注入、响应模型序列化、`/docs` 文档这几层。请求到达时先由 uvicorn 解析成 ASGI 事件，交给 Starlette 的路由分发，命中路由后调用 FastAPI 包装过的处理函数；处理的最后一步才落回 Starlette 构造响应。

## uvicorn 是什么，ASGI 协议是什么

uvicorn 是一个服务器程序：监听 8000 端口，接收 TCP 连接，按 HTTP 协议解析出请求行、请求头、请求体，然后调用负责处理请求的 Python 应用，再把应用产出的响应写回 socket。它自己也支持 WebSocket、HTTP/2、热重载（`--reload` 用 watchfiles 监视文件改动后重启进程）。

ASGI 是 uvicorn 与 Python 应用之间约定好的调用方式。约定应用是一个接收三个参数的异步可调用对象：`scope` 是请求的元数据（方法、路径、请求头、路径参数），`receive` 是异步函数，用来等待并取回客户端发来的事件（请求体分片、断开连接），`send` 是异步函数，用来把响应事件推出去（响应头、响应体分片）。用法是 uvicorn 拿到请求后调用 `await app(scope, receive, send)`，应用通过调用 `send` 把数据一段段写出。SSE 就靠这套机制：响应头发出后，`send` 可以反复推送 `http.response.body` 事件并置 `more_body=True`，服务端边生成边推送，不必等整个响应准备完。WSGI 是更早的同步约定，一次请求占一个线程、只能一次性返回完整响应，做不了 SSE 这种长时间推送。

```python
async def app(scope, receive, send):
    assert scope["type"] == "http"
    await send(
        {
            "type": "http.response.start",
            "status": 200,
            "headers": [(b"content-type", b"text/plain; charset=utf-8")],
        }
    )
    await send({"type": "http.response.body", "body": "你好".encode(), "more_body": False})
```

这段不经过 Starlette 与 FastAPI，就是最原始的 ASGI 应用。Starlette 把 `scope` 包成 `Request`、把 `send` 包成 `Response`，FastAPI 再用 pydantic 处理请求体，所以日常写代码看不到这三个参数。

## 后端如何做流式响应

普通响应在 HTTP 层面带 `Content-Length`，服务端准备好整个 body 才发第一个字节。流式响应改成 `Transfer-Encoding: chunked`：没有总长度，服务端随时可以写一段，每段前面写长度，最后发一个长度为 0 的块表示结束。连接在最后那个块之前一直保持打开，所以浏览器可以先渲染前面收到的文字。

在 ASGI 层面，两者的差别只在 `send` 的调用次数。普通响应发一次 `http.response.start`（状态行与响应头）、一次 `http.response.body` 且 `more_body=False`；流式响应先发 `http.response.start`，然后对内容的每一段各发一次 `http.response.body` 并把 `more_body` 置为 `True`，最后一段再置 `False`。uvicorn 收到 `more_body=True` 的事件就用 chunked 编码立刻写 socket，不等下一次。

FastAPI 里这个分支由 `StreamingResponse` 提供。传入的参数可以是一个可迭代对象、一个同步生成器、一个异步生成器或一个 `async def` 里 `yield` 出来的东西。Starlette 的 `StreamingResponse.__call__` 用 `async for` 消费它，每拿到一块就 `send` 一次 body 事件；客户端断开时 `async for` 被取消，生成器收到 `GeneratorExit`，`finally` 分支照样执行。生成器本身是实现方式上的选择：每 `yield` 一段，控制权交回 `StreamingResponse` 去发这一段，发完再回来继续算下一段，所以「等模型」发生在两帧之间，不占住事件循环，这期间别的请求照常处理。

本项目里对应三个位置：`app/api/chat.py` 的 `chat_stream` 返回 `StreamingResponse(stream_assistant_reply(...), media_type="text/event-stream", headers=SSE_HEADERS)`；`app/services/stream_service.py` 的 `stream_assistant_reply` 是那个异步生成器，每收到模型一个 `delta` 就 `yield encode_frame(...)`；`encode_frame` 拼出 `data: {json}` 加一个空行。SSE 靠这个空行切帧，前端读到空行就知道一帧结束，两个空行之间是一个 `data:` 行。

`media_type` 决定 `Content-Type`，`text/event-stream` 是 SSE 的约定值。另外两个响应头是给中间层看的：`Cache-Control: no-cache` 阻止响应被缓存，`X-Accel-Buffering: no` 告诉 nginx 一类反向代理不要攒够一整块再转发。直接连 uvicorn 做本机开发时没有代理，不加也能看到逐帧输出；上线挂了代理就必须加。命令行验证同样要关掉客户端缓冲，`curl.exe` 加 `-N`，否则它自己攒到结束才打印。

前端接收不能用 `EventSource`，原因是它发不了 `Authorization` 头，拿不到 JWT。改用 `fetch` 加 `response.body.getReader()` 读二进制块，用 `TextDecoder` 解码，按空行切帧。
