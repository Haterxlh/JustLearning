# 主线改为 Agent 应用开发，算法与微调降为支线

> 2026-10-19 晚更新：主线交付物改到本仓库的自建服务，见 `0003-主线交付物改为自建服务.md`。

2026-10-19 本人明确"主线应该是加强自身的 Agent 应用开发能力，算法、微调都是支线"。此前 v3 把 20 小时/周 的工作日晚上 10 小时全部给机考，Agent 与 RAG 排在 W6（10-26）之后，实习项目只留约 20 小时。按新主线重排：20 小时/周 里 Agent 应用开发 11 小时（工作日 3 晚加周六）、算法与机考 6 小时（含周日模拟）、考点与复盘 3 小时；机考目标从冲高分改为过线 180；推理工程从独立一周降为考点选择题与《推理一页纸》；微调 8 小时闭环从 10-31 / 11-07 移到 12 月。

## 考虑过的选项

- 机考保持 10 小时/周、Agent 只吃周末 10 小时：实习中遇到的问题当天晚上跟不进去，Agent 主线变成周末突击。
- 不排固定份额、每周按实习任务临时分配：日计划失去可判定标准，`每日学习进度.md` 的复选框无法记账。

## 后果

- `学习大纲.md` 第十节的时间总账与第八节的里程碑换成 v4 版本；第六节主线项目 A 的节奏写成每周 11 小时。
- `每周进度规划.md` 的 W5 ~ W8 重写：W5 实习项目摸底与工具层，W6 RAG 与评测，W7 Agent 编排与模块 V1，W8 评测、讲述稿与简历。
- 机考每周 3 题加 1 次限时模拟；`diy-llm` 只剩 8 小时（《推理一页纸》与 ch4 对照），6 个作业一个都不跑。
- 12 月之前不排微调；12 月按 `学习大纲.md` 第十二节做 8 小时闭环。
