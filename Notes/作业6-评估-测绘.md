## 7. 核心问题：【原文 + 估计】单张 RTX 4070 Super 12GB 单卡能不能做？

### 结论：**能，而且非常轻松。GPU 甚至不是必需品。**

**支撑理由（全部基于原文事实）：**

1. **官方演示模型是 gpt2**。原文 `model='openai-community/gpt2'`，5 个 config 与 3 个 report 全部一致。这是一个体量极小的模型。
   【估计，不在抓取内容中】gpt2 为 124M 参数，fp16 权重约 0.25 GB、fp32 约 0.5 GB。12GB 显存对它而言是几十倍冗余。
2. **官方 demo 本身就是 CPU 版**。原文 `device="cpu"`，且 `# device='cuda',` 被注释；作者机器是 macOS + `/opt/miniconda3`，路径 `/Users/xuhu.6736/`。**作业的参考实现在 CPU 上就已经完整跑通了。**
3. **评测规模是玩具级**：`count=10`（评测集 10 条）、`limit=1`（每任务 1 条）、`eval_batch_size=5`、`max_gen_toks=512`、`max_length=1024`。全部可塞进 12GB，甚至可塞进 4GB。
4. **数据量极小**：见第 8 节，评测集原始文件合计 MB 级。
5. **唯一的时间风险点不是显存，是"不裁剪就跑"**：原文日志显示，若不设 `limit`，仅 4 个 zero-shot 任务就要跑 6477 条 512-token 生成请求，ETA 2:50:13（CPU）。这个"3 小时"在 4070S 上会被大幅压缩。
   【估计，不在抓取内容中】gpt2 在 4070S 上做 512-token 贪心解码，吞吐大致是 CPU 的 10–50 倍，即上述 3 小时量级可压到数分钟到二十几分钟。该倍数是我基于经验的主观估计。

**如果要在 4070S 上做"更真实"的对比评测（以下是【推断，不在抓取内容中】）：**

| 被测模型 | 显存可行性（12GB） | 备注 |
|---|---|---|
| gpt2（官方） | 轻松 | 官方路径 |
| Qwen2.5-1.5B（原文注释里那个） | 可以，fp16 约 3GB | 最省事的"升级版" |
| 7B–8B fp16 | **不行**，权重约 15GB | 需量化或分片 |
| 7B–8B 4bit（QLoRA/GPTQ/AWQ） | 可以，约 4–6GB | 需装 bitsandbytes/GPTQModel |
| Qwen2.5-14B（原文注释里那个） | 本地 fp16 不行；**但它是走 DashScope API 的**，无本地显存需求 | 见第 9 节 |

**更省事的路线（推荐，依据原文已有注释模板）**：用 evalscope 的 `eval_type='openai_api'` 打云端 API，本地完全不占显存。原文 `evalscope_demo.py` 已经把这段模板写好放在注释里。

**限制与坑（以下为【推断，不在抓取内容中】）：**

1. **lm-eval 那一半没有 API 模板。** 抓到的 `lm_eval_demo.py` 用的是 `HFLM`（HuggingFace 本地模型类），全文没有任何 API 用法。要用 API 必须自己改成 lm-eval 的 API model type（例如 `openai-completions` / `local-completions` / `litellm`），并注意很多任务依赖 loglikelihood，而多数云 API 不返回 logprobs。
   - 具体地：`arc_easy`、`piqa`、`lambada` 是 loglikelihood 型任务。即使 evalscope 侧走 API，问题不大（evalscope 的 `data_collection` 用的是生成 + 抽取答案的 `acc`/`Average` 路径）；但 lm-eval 侧的 `arc_easy`/`piqa`/`lambada` 走 API 会受限。**这是我的框架知识推断，不在抓取内容中，需实测确认。**

2. `humaneval` 走 API 时需要在本地沙箱执行生成代码（原文有 `os.environ["HF_ALLOW_CODE_EVAL"] = "1"` 与 `confirm_run_unsafe_code=True`），纯 API 不能省掉本地执行环境。

4. **纯 API 反而更有价值**：因为原文里 gpt2 在所有 benchmark 上**得分全是 0.0**，跑 gpt2 看不出"评测框架在工作"。换成云端真模型，才能产出有意义的分数，也才有资格写进你的项目经历。

**推荐的纯 API 路线（【推断】）：**
把 `evalscope_demo.py` 里被注释的 4 行激活（换成你自己的 OpenAI 兼容端点与 key），或者直接按 evalscope 官方 README 的 `evalscope eval ... --eval-type openai_api` 跑；lm-eval 半边可以保留 gpt2 本地小跑以"证明框架跑通"，把"真实对比评测"放在 evalscope 侧用 API 完成。
